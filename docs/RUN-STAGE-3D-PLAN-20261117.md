**현재 단계: 구현.** 아래 「계획 확정」부터가 2026-11-17 구현 세션이 코드를 읽고 정한 내용이고, 끝의 「구현 결과」에 실제 결과를 적는다. 공통 규격은 [공통 계획](../../_shared/RUN-STAGE-3D-PLAN-20261117.md)에 있다.

## 한 줄 요약

4장의 적용 문제 「물이 들어오는 갯벌」 한 개를, 부리가 나무 탐사길을 걸어 갯벌 생물을 살펴보고 물이 들어오기 전에 돌아오는 3D 걷기로 바꾼다.

## 바꿀 자리

- 3~4학년 「지구와 바다」. 다섯 장이고 장마다 관찰(a) → 비교(b) → 도전(c) → 적용(d) 네 화면이다.
- 대상은 4장 밀물·썰물 관측소의 적용 화면 `s4d`에 있는 `tide-safety` 문제 한 개다.
- 2026-11-17에 반복되던 확장 문제를 40개에서 20개로 줄였다(`docs/reviews/FLOW-STREAMLINE-20261117.md`). 그래서 **문제를 더하지 않고 있던 문제 하나를 바꾼다.** 문제 수와 완료 조건은 그대로다.
- 관찰 `s4a`와 비교 `s4b`는 바꾸지 않는다. 물 높이를 직접 비교해 기록하는 것이 이 장의 학습이다.
- 관련 파일: `src/challenge-data.js`(문제 자료), `src/challenges.js`(문제 화면, `scenes`의 `tide-safety`), `src/state.js`(4장 판정 118·148행 부근), `src/data.js`(물 높이 자료).

## 지금 방식과 바뀐 방식

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 조작 | 장면 그림을 보고 답을 고른다 | 방향판으로 탐사길을 걷고, 생물 앞에서 '살펴보기'를 누른다 |
| 판단 | 물이 들어올 때 어떻게 할지 고른다 | 시계와 물 높이를 보고 스스로 돌아설 때를 정한다 |
| 화면 | 생성한 장면 그림 한 장 | 해안 데크에서 갯벌로 뻗은 3D 탐사길 |

### 점프를 넣지 않는다

이 스테이지는 점프 버튼이 없다. 갯벌에서 물길(갯골)을 뛰어넘는 것은 실제로 위험한 행동이고, 이 프로젝트의 안전 장면은 "울타리가 있는 안전한 탐사길"을 따라가는 것이다. 그래서 캐릭터는 탐사길과 데크 위로만 다닌다. 갯벌 바닥으로 내려가거나 생물을 줍는 조작도 넣지 않는다(`mudflat-protect` 장면의 내용: 관찰 데크에서 보고, 게 구멍과 갈대는 그대로 둔다).

## 과학 개념과 조작

| 개념 | 걷기에서 하는 일 |
|---|---|
| 바닷물의 높이는 시간에 따라 높아졌다 낮아진다 | 화면의 시계가 가는 동안 탐사길 옆의 물 높이가 달라진다 |
| 물이 빠졌을 때 갯벌이 드러난다 | 물이 낮을 때 탐사길 끝까지 갈 수 있고 갯벌 생물이 보인다 |
| 물이 들어오기 시작하면 안전한 길로 돌아온다 | 물이 높아지기 시작하면 돌아서서 데크로 온다 |

### 지켜야 할 제한

- `src/data.js` 71행: "한 칸은 2시간인 학습용 관측 모형이다. 실제 밀물·썰물 시각과 높이는 장소와 날짜에 따라 다르다." 걷기 화면에도 이 문구를 둔다.
- 물 높이는 기존 `tideHeight` 값 [28, 45, 66, 83, 66, 45, 28]만 쓴다. 칸 사이는 매끄럽게 이어 보여 주되 새 값을 만들지 않는다.
- 물에 빠지거나 휩쓸리는 연출을 하지 않는다. 물이 탐사길 높이에 가까워지면 수달 모아가 호루라기로 부르고 부리가 데크로 돌아온다. 그 뒤 자기 4장 기록을 다시 보고 다시 해 본다.
- 남은 시간을 숫자로 재촉하지 않는다. 판단의 근거는 시계와 물 높이 표시다.
- 실제 갯벌에서는 물때를 미리 확인하고 어른과 함께 간다는 안내를 끝에 넣는다.

## 코스 구성

1. **출발 전:** 자기가 `s4a`에서 저장한 두 순간의 기록을 보고, 언제 나갔다가 언제 돌아올지 예상한다.
2. **나가는 길:** 물이 낮아지는 동안 데크에서 탐사길 끝으로 걷는다. 관찰 지점 세 곳(게, 짱뚱어, 갈대)에서 살펴본다.
3. **돌아오는 길:** 물이 높아지기 시작하면 돌아선다. 데크에 도착하면 끝난다.
4. **비교:** 예상한 때와 실제로 돌아선 때를 나란히 보여 준다.

## 기술, 검증, 배포

- Three.js는 npm `three` 0.186.1이 이미 있다. 지금은 `src/globe.js`(지구 돌려 보기)만 쓰고 `src/main.js` 166행 부근에서 필요할 때 불러온다. 같은 방식을 쓴다.
- WebGL을 쓸 수 없을 때 지구는 2D 캔버스로 넘어가고 `settings.flatGlobe` 설정이 있다. 걷기 스테이지도 같은 설정을 따른다.
- 방향판은 `src/map-controls.js`의 `bindDirectionPad`를 다시 쓴다.
- 검증 명령: `npm test`(`node --test tests/*.test.js`), `npm run check:layout`, `npm run build`.
- **운영 주소는 운영 시트 G열의 https://earth-and-ocean-explorer.yelsam.workers.dev/ 다**(2026-11-17 시트 대조로 바로잡음. 처음에 적었던 GitHub Pages 주소는 운영 주소가 아니다). Cloudflare Worker `earth-and-ocean-explorer`에 직접 배포한다. 실제 절차는 가장 최근 배포 기록인 `docs/reviews/ART-FLOW-UPGRADE-20261117.md`의 「운영 반영」을 따른다. `main`에 푸시하면 `.github/workflows/deploy.yml`이 GitHub Pages에도 올리지만, 그 성공은 운영 배포 완료의 근거가 아니다.

## 계획 확정 · 2026-11-17 구현 세션

코드를 읽어 「시작 전에 확인할 것」을 해결하고, 위 문서에서 실제 코드와 달랐던 곳을 바로잡았다.

### 확인한 것

- `tide-safety`는 `src/challenge-data.js`의 두 가지 고르기(`multi`) 문제다. 보기 0 「안내에 따라 안전한 길로 돌아가요」, 1 「낮은 바위에서 계속 놀아요」, 2 「현장의 안전 안내와 실제 물때를 확인해요」, 3 「게임 속 시각만 믿고 바다에 가요」, 정답은 `['0','2']`다.
- 완료 기록은 `state.research[4].answers['tide-safety']`(고른 보기 id 배열)와 `state.research[4].solved`(문제 id 배열)다. 판정은 `correctResponse(task, response)` 하나다. 위 「연결과 저장」의 "`research[4]`에 기록"은 이 두 필드를 뜻한다. 저장 필드는 더하지 않는다.
- 모아(수달) 그림은 `public/assets/moa.webp`(도움말·세운 그림), `public/assets/moa-map.webp`(지도), `public/assets/dialogue/moa.webp`(대화 초상)다.
- 움직임 줄이기는 앱 설정이 아니라 기기 설정(`prefers-reduced-motion`)을 읽는다. 앱 설정에는 「2D 지구 대체」(`settings.flatGlobe`)가 있다. 둘 중 하나라도 켜져 있으면 기존 2D 문제로 연다.
- 운영 주소와 저장소는 지휘 세션이 2026-11-17에 시트 G·H열과 대조했다(위 「기술, 검증, 배포」).

### 바로잡은 것

- **물이 낮아졌다가 높아지는 코스는 만들 수 없다.** `tideHeight`는 06:00~18:00 일곱 칸 [28, 45, 66, 83, 66, 45, 28]뿐이라 물이 낮아진 뒤(12:00→18:00) 다시 높아지는 칸이 없다. 18:00 뒤를 이어 붙이면 모형에 없는 시각·값을 만드는 것이라 제한과 어긋난다. 그래서 걷기는 **06:00(가장 낮음 28) → 12:00(가장 높음 83)** 구간만 쓴다. 물이 가장 낮아 갯벌이 드러난 때 나가고, 물이 들어오는 동안 스스로 돌아설 때를 정한다. 칸 사이는 직선으로 이어 보여 준다.
- 걷기에는 떨어질 곳이 없다(난간 안쪽만 걷는다). 그래서 "떨어지면 체크포인트로"는 해당이 없고, 다시 할 때는 데크에서 시작한다.
- 물리 예제(`games_fps`)의 Octree·Capsule 충돌은 쓰지 않는다. 점프와 낙하가 없어 걸을 수 있는 네모 구역 안으로 위치를 묶는 것으로 충분하다. 프레임 시간을 0.05초로 자르는 것과 화면 기준 방향 입력은 그대로 따른다.
- 카메라는 옆에서 비스듬히 내려다보며 따라간다. 나갈 때는 오른쪽, 돌아올 때는 왼쪽이라 두 방향 모두 앞이 보이고, 기둥에 닿는 물 높이가 잘 보인다.

### 판정 연결

걷기에서 한 행동을 기존 보기 id로 옮기고, 맞았는지는 기존 `correctResponse`가 정한다.

| 걷기에서 한 일 | 기록되는 보기 |
|---|---|
| 출발 전에 데크의 물때 안내판을 살펴봄 | 2 「현장의 안전 안내와 실제 물때를 확인해요」 |
| 안내판을 보지 않고 탐사길로 나감 | 3 「게임 속 시각만 믿고 바다에 가요」 |
| 물이 경고 눈금에 닿기 전에 스스로 데크로 돌아옴 | 0 「안내에 따라 안전한 길로 돌아가요」 |
| 경고 눈금까지 남아 있다가 모아가 불러서 돌아옴 | 1 「낮은 바위에서 계속 놀아요」 |

틀리면 모아가 걷기에서 한 일에 맞는 힌트를 주고 데크에서 다시 한다. 세 번 틀리면 「기존 방식으로 하기」를 권한다. 예상(언제쯤 돌아올지)은 판정하지 않고 끝에 실제와 나란히 보여 준다. 예상은 저장하지 않는다.

- 갯벌은 바다 쪽으로 낮아지는 비탈이고 물은 수평면이다. 물 높이가 오르면 먼 곳부터 잠긴다. 탐사길 윗면은 12:00의 물보다 높아 잠기지 않는다.
- 탐사길로 3m 넘게 나갔다가 데크로 돌아오면 끝난다. 나가지 않고 10:00이 되면 탐사길을 닫고 06:00부터 다시 한다(판정 없음).
- 조작: 왼쪽 아래 방향판(4방향), 오른쪽 아래 「살펴보기」. 키보드는 방향키·WASD, Space·Enter. 점프는 없다.

걸어 보고 고친 것

- 갯벌 비탈이 가파르면(1m에 4cm) 탐사길 바로 뒤의 게·짱뚱어가 길에 가려 보이지 않았다. 비탈을 1m에 2.5cm로 줄이고 생물을 표시 오른쪽 뒤 갯벌에 두었으며, 밝은 젖은 모래 자리를 깔았다.
- 갈대는 키가 커서 물이 들어와도 물 위로 보여야 한다. 잠김 판정에서 뺐다. 게·짱뚱어만 갯벌 바닥이 잠기면 보이지 않는다.
- 세운 그림은 가장자리를 오려 깊이를 쓰고 물보다 먼저 그린다. 물에 잠긴 아랫부분이 수면 아래로 보이고 난간·기둥과 앞뒤가 맞는다. 멀리 있는 배는 수면과 함께 오르내린다.
- 부리가 모아·짱이와 겹쳐 서거나 안내판·난간 앞 소품을 뚫고 지나가지 않게 걸을 수 있는 범위를 줄였다. 넓은 데크에서 좁은 탐사길로 들어설 때는 길 안쪽으로 붙여 준다.
- 화면 겹침: 세로 태블릿(768×1024)에서 생물 카드가 방향판·살펴보기 버튼과 겹쳐 카드를 위로 올렸다. 좁은 화면에서는 위쪽 표시를 두 줄로 나눈다. 출발 전 카드는 낮은 화면에서 예상 보기를 한 줄로 놓는다.
- 물 높이 막대가 06:00에 0으로 보이던 것을 0~탐사길 높이 기준으로 바꿨다.
